Two Review Maps, from real pull requests

A Review Map is a review agenda: the smallest set of judgments a change asks of you, each with the code that settles it attached. These two were produced by accountable-review against open pull requests in public Rails codebases, so every file:line citation on them resolves — you can follow any claim straight into the repository it is about.

They are ordinary output, not showcases: no page was edited after the run produced it.

RubyGems.org

Every confirmed gem ownership now leaves a durable record of who held it

Eleven files that all look safe: a new table, the callbacks that keep it in step with the live one, and a backfill task. Nothing reads the new table yet, so what a reviewer has to decide is almost entirely about code the diff never opened — which paths destroy an ownership without running a callback, and which of them now close a tenure for someone whose access continues anyway.

How these were made

Both generated on 2026-09-21 with accountable-review 1.0.1, at the default --effort high and without --mentor. The page format moves between releases, so the version is recorded rather than implied: a map produced by a later release may not look like these. Provenance for each page.

A Review Map is a pass over a change, not an audit of it, and it carries no verdict on either pull request — see what a Review Map cannot do.
