Primer ActiveModel::Dirty
archived_at_changed? vs saved_change_to_archived_at?

Every ActiveRecord attribute carries two questions, and they are true at different moments. archived_at_changed? asks whether the value in memory differs from the one loaded from the row — true before the save and false after it. saved_change_to_archived_at? asks what the save just wrote, and is only true after it.

Which one a callback wants therefore depends on when it runs. A before_save that asks the second question never fires; an after_commit that asks the first one never fires either, and both failures are silent.

The callback at {{PATH}}:{{LINE}} runs after the write, so it is the second form it has to ask.
api.rubyonrails.org
In practice 
post = Post.find(1)
post.title = "new"
post.title_changed?          # => true
post.save
post.title_changed?          # => false
post.saved_change_to_title?  # => true

Both predicates are generated per attribute, so they exist for every column without being written anywhere.

Pundit Primer Pundit::Authorization
authorize raises; it does not return false

authorize looks up a policy class by the record's class name, calls the question method, and raises Pundit::NotAuthorizedError when the answer is false. It is a guard clause, not a predicate — so a controller that treats its return value as a boolean has written a branch that never runs.

The rescue that turns it into a response is app-level and opt-in, which is why the status a denied request gets is a decision this repository makes rather than one the gem makes.

The action at {{PATH}}:{{LINE}} relies on that raise reaching the handler rather than on a returned value.
github.com/varvet/pundit
In practice 
class PostPolicy
  def update?
    user.admin?
  end
end

authorize @post, :update?
# => raises Pundit::NotAuthorizedError

The lookup is by class name, so a subclass with no policy of its own falls back to nothing and raises on lookup instead.
