Primer Sidekiq::Job
A job runs again after a failure, from the top

A raised exception is not a rollback: the job is re-enqueued and its whole perform runs again, including everything that already succeeded before the raise. Idempotence is therefore the job's own responsibility rather than something the queue provides.

The stamp at app/models/project.rb:4 is written inside a job that can run twice, so the second run has to be a no-op.

class MailJob
  def perform(id)
    charge!(id)   # ran
    notify!(id)   # raised
  end
end
# => perform(id) runs again, charge! included

Retries are exponential by default, so the repeat is later rather than immediate — which is what makes it easy to miss in development.
