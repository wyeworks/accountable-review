Understanding Rust tokio::select!
The losing branch is dropped, not paused

When one branch of select! completes, every other branch's future is dropped where it stands — at whichever .await it had reached. Work done before that await has happened; work after it never will. A branch is cancellation safe only if stopping it at any await leaves nothing half-done.

The write at crates/api/src/handlers/projects.rs:88 awaits twice, so a timeout between them leaves the first write committed alone.
