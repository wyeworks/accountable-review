# Flow split — rails-only-small

Grouping principle: **one flow per behaviour a reader has to hold at once**, which here is
the write and the read. Archival is the write; the selectable list is the read whose meaning
the write changes. Both cut through controller and model; neither is a directory.

```
Flow A — Archiving a project              primary
Flow B — Listing projects to choose from  primary, and entirely outside the diff
```

`Flow B` is the one that justifies the split. It contains no changed file at all — its
subject, `app/queries/active_projects.rb`, is unchanged — and it exists because after this
PR the list means something it did not mean before. A split by directory cannot produce it.

Leftover, not a flow of its own:

| | Label | Why |
|---|---|---|
| Slug uniqueness validation | secondary | Independently reviewable, outside the archival mental model. `app/models/project.rb:6` |
| `db/schema.rb` | supporting | Generated by the migration; a ledger row, not a unit |

Cross-cutting, for § 5: the application-versus-database invariant table — the new slug
uniqueness validation lives in Rails only, while `db/schema.rb` has no unique index on
`projects.slug`. Migration safety belongs there too: `add_column` plus `add_index`, not
concurrent, on a table this size.
